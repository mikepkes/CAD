VibeCAD Usability Review

70 findings from three reviews, 2026-11-01. For deciding what to fix.

What was reviewed, and how

Three reviewers drove the running app with real clicks and keys (Playwright). One covered the core modelling workflow on desktop at 1440×900. One covered the concept panels and power features at 1440×900. One covered the customize viewer, first run, accessibility and responsiveness on desktop (1280×800, 1440×900) and on a phone (390×844, touch). This page puts their condensed reports (docs/ux/modelling.md, panels.md, viewer.md) next to the screenshots they took.

  • 70 findings: 25 modelling, 22 panels, 23 viewer. 56 have screenshots (cropped, with the problem outlined and numbered) and 22 have a small Suggested mock-up. Tap a screenshot to enlarge it.
  • Fixed in main: M1, M2 and M3 (bad expressions are refused, renames follow, failed features show). 5 more are partly fixed by later commits (a source check, not re-tested in a browser); the card says what is left.
  • Severity is as the report states it. An asterisk (Minor*) means the report gave none and I inferred it from the description.
  • Line numbers in the Cause lines are from the code at review time and have since moved. Screenshots are from the same build, so they still show the old state of anything fixed since.
  • Decisions (Fix, Later, Won't fix) only highlight here. Nothing is saved, so use "Decisions as text" to copy your list.

Modelling 25 findings

The core workflow: a phone stand from a blank page, edits to early features, error cases, save and open, the ring, pick-behind, shortcuts. Desktop, 1440×900. Source: docs/ux/modelling.md.

M1

Unknown or invalid expressions are accepted silently and collapse the geometry

BlockerFixed

Fixed in main (d277b07): a typed value that doesn't read, or names no parameter, is refused with a sentence. The inline dimension editor stays open. The Extrude panel and feature edits refuse it too. sketch.addDimension refuses it for agents and MCP. len = 80 creates the parameter.

Details

Steps to reproduce

  1. Open a new sketch on XZ and draw a rectangle.
  2. Pick the Dimension tool and dimension the bottom edge.
  3. Type base_len (never defined), len=80 or 80+ and press Enter.
  4. Do the same for an Extrude distance in the Extrude dialog or the Inspector.

What happens

The value is stored and evaluates to 0, so the rectangle collapses to a point. The Inspector shows 0.000 in green, and the strip still says "All features built".

Expected

A bad or unknown expression is refused with an inline error and the field stays open.

Cause sketch.addDimension stores value: 0 without validating (builtins.ts ~1927). evalExpr falls back to 0 with a warning nothing shows (solver/compile.ts:65-75). The inline-edit and extrude commits don't validate either.

Suggested fix

Validate against the scope before dispatching (inline dimension, Inspector, Extrude panel) and show an inline error. The commands should reject unknown names too, since MCP and agents use them. Offer to create a missing parameter, accept name = expr, and show compile.warnings.

M2

Renaming a parameter silently breaks every reference to it

BlockerFixed

Fixed in main (d277b07): a rename rewrites every use (dimensions, features, joints, planes, other parameters, intents, configuration cells, commands) in one undoable step.

Details

Steps to reproduce

  1. Add a parameter base_len = 80 and use it in a sketch dimension.
  2. Rename the parameter in the Parameters panel (here to blen).

What happens

References still use the old name and evaluate to 0, and the dimension collapses. The status bar says "Added parameter".

Expected

Every reference follows the rename, in one undoable edit, or the rename is refused.

Cause renameParameter only edits the parameter.add op (store.ts:918-921).

Suggested fix

Rewrite every expression (dimensions, features, parameters, configurations) through the expression AST in one undoable edit, or refuse the rename.

M3

Failed features are reported as built

BlockerFixed

Fixed in main (d277b07): a feature the kernel couldn't build carries its error on its chip, card and timeline row, and the strip says "3 · Fillet failed: 2 of 3 built".

Details

Steps to reproduce

  1. Build a base extrude, then a boss.
  2. Add a Round edges (fillet) with a radius too big for the geometry, or extrude an open or empty profile.

What happens

Kernel errors leave normal chips, pins and timeline rows. The strip says "All N features built" and the old geometry is kept quietly.

Expected

The failing feature is marked with its error, and the strip says how many built.

Cause featureCatalog.ts:200 sets error: op.error and never solids[id].error. The UI already renders row.error.

Suggested fix

error: op.error ?? solid?.error, plus warnings, and a toast when a feature goes from ok to error.

M4

Push/Pull on a face moves the wrong dimension and destroys formulas

Major
Details

Steps to reproduce

  1. Make a plate by extruding a sketch.
  2. Click the top face to open its card.
  3. Press ＋ on the card (or edit the number).

What happens

＋ on a top or end face changes the extrude depth instead of moving that face. On an extrude whose distance is a formula, ＋ replaces it with a literal 0.5, and the minimum clamp flips the back. Card edits overwrite formulas the same way.

Expected

Push/Pull moves the face you clicked. Formulas survive, or are edited at their source.

Cause pushTargetOf ignores the face normal (workbench.ts:253-272). pushTo overwrites expressions (:292-301). The catalog clamps to 0.5 (featureCatalog.ts:55).

Suggested fix

Offer Push/Pull only on caps parallel to the extrude direction. Show formulas read-only with "edit formula…", or edit the referenced parameter. Allow negative values or add a Reverse toggle.

M5

Destructive actions have no guard (Open, deleting a parameter in use)

Major
Details

Steps to reproduce

  1. Build a model that uses a parameter.
  2. Delete the parameter (✕ in the Parameters panel).
  3. Separately: choose Open and pick a file.

What happens

Open replaces the document with no prompt and no undo, and overwrites the autosave. Deleting a parameter that's in use asks nothing and collapses the model.

Expected

Open confirms, like New does, or is undoable. Deleting a used parameter says what uses it.

Suggested fix

Confirm Open, like New (or make it undoable). Deleting a parameter in use lists what uses it and offers to inline its value. Add a dirty indicator.

M7

Major
Details

Steps to reproduce

  2. Click the X value 40.0 mm.
  3. Press digit keys, or type width*2 and Enter, or try 800.

What happens

Typing starts only on Enter. Expressions like width*2 are discarded, and 800 is silently clamped to 500.

Expected

The ConstraintBar grows a row, so the next click lands on something else. Sketch chrome uses about 300–370 px of 900. Clicking a line's endpoint selects the line, not the point.

Expected

M9

Rectangles don't attach to what they snap to

Major
Details

Steps to reproduce

  1. Start a sketch.
  2. With the Rectangle tool, click at the origin, then drag out the opposite corner.
  3. Look at the Inspector.

What happens

A rectangle snapped to the origin gets no coincident constraint, so it has 4 DOF instead of 2. Long-press pick-behind does nothing in a sketch.

Expected

Snapped corners get coincident or on-curve constraints, as the line tool does.

Cause handleRectClick drops snap.ref (interactions.ts:750-760). The same goes for the shape variants and the polygon.

Suggested fix

Carry each corner's snap and add coincident or on-curve constraints, as the line tool does. Enable long-press in sketches.
